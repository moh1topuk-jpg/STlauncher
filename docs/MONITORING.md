# Мониторинг онлайна

Лаунчер показывает график онлайна сервера. Сам по себе он может замерять онлайн только
пока открыт, поэтому на свежей установке график почти пустой. Чтобы история была общей и
полной, её собирает отдельный «сборщик» и публикует одним JSON-файлом, который лаунчер
читает при запуске.

## Почему именно так

Бесплатного публичного API с историей онлайна не существует — это проверялось:

| Источник | История | Итог |
| --- | --- | --- |
| minecraft-statistic.net | была (24 ч, шаг 10 мин) | API отключён: эндпоинт отвечает `API is not available at the moment` |
| LiteByte | есть | ключ выдаётся на посетителя, 10 запросов/мин — раздать его игрокам нельзя |
| mcstatus.io, mcstatus.xyz, mcsrvstat.us | нет | тот же пинг, который лаунчер делает сам |
| Top-Minecrafter | нет | зато даёт агрегаты, которых не посчитать локально |

Top-Minecrafter отдаёт средний онлайн за неделю, рекорд с датой, аптайм и место в
рейтинге. Именно они и показываются с первого запуска, пока график ещё не накопился.
Но его ключ **нельзя** зашивать в лаунчер: тем же ключом открывается список
проголосовавших игроков и донатов, а лимит в 300 запросов в минуту общий на всех.

Поэтому ключ живёт в сборщике, а игроки читают готовый публичный JSON без ключа.

## Что нужно

Аккаунт Cloudflare (бесплатный, без карты). **DNS домена трогать не нужно** — воркер
работает на адресе вида `https://<имя>.<аккаунт>.workers.dev/`. Перенос домена в
Cloudflare потребовался бы только ради красивого адреса вроде `stats.showtime.su`, а
игроки этот адрес всё равно не видят: он прописан в `catalog.json`.

## Настройка

1. **Создать воркер.** [dash.cloudflare.com](https://dash.cloudflare.com/) → *Workers &
   Pages* → *Create* → *Start with Hello World!* → имя, например `showtime-stats` →
   *Deploy*.

2. **Вставить код.** *Edit code* → заменить содержимое файлом
   [`docs/monitoring/worker.js`](monitoring/worker.js) → *Deploy*.

3. **Создать хранилище.** *Storage & Databases* → *KV* → *Create Instance* → имя,
   например `stlauncher-stats`.

4. **Привязать хранилище.** Воркер → *Settings* → *Bindings* → *Add* → *KV namespace*:
   - Variable name: `STATS`
   - KV namespace: `stlauncher-stats`

5. **Добавить переменные.** Там же, *Settings* → *Variables and Secrets*:

   | Тип | Имя | Значение |
   | --- | --- | --- |
   | Secret | `TOPMC_KEY` | ключ из личного кабинета Top-Minecrafter |
   | Text | `SERVER_ID` | `6689` |
   | Text | `SERVER_ADDRESS` | `mc.showtime.su` |

   Ключ обязательно **Secret**, а не Text: так он не показывается в интерфейсе и не
   попадает в логи.

6. **Включить расписание.** *Settings* → *Trigger Events* → *Add* → *Cron Trigger* →
   `*/5 * * * *` (раз в пять минут).

7. **Проверить.** Открыть `https://<имя>.<аккаунт>.workers.dev/` в браузере. Сразу после
   создания придёт пустой ответ (`"sampleCount": 0`) — это нормально, первое обращение
   само запускает замер. Обновите страницу через минуту: появятся `server`, `summary` и
   `ranges`.

8. **Опубликовать адрес.** Добавить в корень [`catalog.json`](../catalog.json):

   ```json
   "serverStatsUrl": "https://showtime-stats.ваш-аккаунт.workers.dev/",
   ```

   Всё: лаунчеры подхватят адрес при следующем запуске, **новая версия не нужна**.
   Убрать строку — и лаунчер вернётся к собственным замерам.

Пока адрес не опубликован, его можно вписать вручную в *Настройки → Для разработчиков →
Адрес сборщика статистики*, чтобы проверить сборщик до публикации.

## Что отдаёт сборщик

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-09-17T21:30:00.000Z",
  "sampleCount": 2197,
  "server":  { "name": "ShowTime", "address": "mc.showtime.su",
               "online": 33, "max": 2026, "isOnline": true },
  "summary": { "averageWeek": 40, "peak": 366,
               "peakAt": "2026-08-07T20:49:32.000Z", "uptime": 100, "rank": 26 },
  "ranges":  {
    "day":  { "from": "…", "to": "…", "buckets": [ { "t": "…", "avg": 34.2, "peak": 41 } ] },
    "week": { "from": "…", "to": "…", "buckets": [ { "t": "…", "avg": null, "peak": null } ] }
  }
}
```

`avg: null` — это **пропуск**, а не ноль: сборщик в этот час не работал. Лаунчер рисует
пропуск иначе, чем час, когда на сервере никого не было.

Бакеты считаются в момент замера и складываются в KV готовыми, а отдача — просто чтение
файла. Это не оптимизация ради оптимизации: на бесплатном плане у запроса есть 10 мс
процессорного времени, и считать бакеты на каждый запуск лаунчера в него не влезет.
Расчёт на восьми днях данных занимает около 1 мс и делается 288 раз в сутки.

## Расходы и лимиты

Бесплатного плана хватает с большим запасом:

| Ресурс | Лимит free | Расход |
| --- | --- | --- |
| Запросы к воркеру | 100 000 / сутки | по одному на запуск лаунчера |
| Cron-триггеры | 5 на аккаунт | 1 |
| Записи в KV | 1 000 / сутки | 576 (две записи каждые 5 минут) |
| Чтения из KV | 100 000 / сутки | по одному на запрос |
| Объём KV | 1 ГБ | ~42 КБ |

Хранятся 8 суток замеров — недельный график плюс запас. Лимит Top-Minecrafter (300
запросов в минуту) расходует только сборщик: 1 запрос в 5 минут.

## Если сборщик недоступен

Лаунчер к нему не привязан жёстко:

1. нет ответа → берётся сохранённая копия (`meta/server-stats.json`) с пометкой,
   что данные не свежие;
2. копии нет или она старше 6 часов → график строится по собственным замерам лаунчера,
   как будто сборщика нет вовсе;
3. адрес не задан → всё работает как раньше.

## Безопасность ключа

- ключ хранится в Secret воркера и не попадает ни в лаунчер, ни в репозиторий;
- если он всё же где-то засветился — в личном кабинете Top-Minecrafter есть кнопка
  «Перевыпустить»; после этого достаточно обновить Secret в воркере, **клиенты трогать
  не нужно**;
- в репозиторий этот ключ коммитить нельзя: репозиторий публичный.
