# Каталог сервера — `catalog.json`

[`catalog.json`](../catalog.json) в корне репозитория описывает всё, что относится к
серверу: рекомендуемую сборку, её моды и адреса служебных сервисов. Лаунчер читает его при
каждом запуске отсюда:

```
https://raw.githubusercontent.com/moh1topuk-jpg/STlauncher/main/catalog.json
```

Поэтому **всё, что задаётся в каталоге, меняется без выпуска новой версии лаунчера** —
достаточно отредактировать файл в `main` (хоть через веб-интерфейс GitHub). Игроки
получат изменения при следующем запуске.

Если GitHub недоступен, лаунчер берёт каталог через зеркало (см. [updates.md](updates.md)),
а если недоступно и оно — последнюю сохранённую копию.

## Структура

```json
{
  "schemaVersion": 1,
  "name": "Showtime Server",
  "serverStatsUrl": "https://showtime-stats.moh1topuk.workers.dev/",
  "updateFeedUrl": "https://showtime-updates.moh1topuk.workers.dev/",
  "sections": [
    {
      "id": "server-mods",
      "title": "Моды сервера",
      "items": [
        {
          "id": "sodium",
          "type": "mod",
          "name": "Sodium",
          "description": "Повышает FPS",
          "required": true,
          "source": { "kind": "modrinth", "project": "sodium", "version": "mc1.21.11-0.8.12-fabric" }
        }
      ]
    }
  ],
  "builds": [
    {
      "id": "showtime-fabric-1.21.11",
      "name": "Showtime — Fabric 1.21.11",
      "recommended": true,
      "gameVersion": "1.21.11",
      "loader": "fabric",
      "loaderVersion": "0.19.5",
      "memoryMb": 4096,
      "serverName": "Showtime",
      "serverAddress": "mc.showtime.su",
      "items": ["sodium"]
    }
  ]
}
```

### Корень

| Поле | Что делает |
| --- | --- |
| `serverStatsUrl` | Адрес сборщика статистики онлайна ([monitoring.md](monitoring.md)). Нет поля — лаунчер строит график по своим замерам. |
| `updateFeedUrl` | Адрес зеркала обновлений ([updates.md](updates.md)). Нет поля — обновления идут напрямую с GitHub. |

### Элементы (`sections[].items[]`)

| Поле | Что делает |
| --- | --- |
| `id` | Уникальный идентификатор; на него ссылаются сборки. |
| `type` | `mod`, `resourcepack`, `shaderpack`, `config` или `other` — определяет папку. |
| `targetPath` | Папка вручную. Так можно добавить новый тип контента без обновления лаунчера. |
| `source.kind` | `modrinth` (`project`, `version`) или `direct` (`url`, `fileName`, `sha1`/`sha512`). |

### Сборки (`builds[]`)

Сборка с `"recommended": true` создаётся у игрока автоматически. Без флага
рекомендуемой считается первая. `items` — список `id` элементов, которые в неё входят.

## Как обновляется сборка у игроков

**Каталог — источник истины**, а не Modrinth. При каждом запуске лаунчер сверяет сборку,
созданную из каталога, с этим файлом:

- **версия игры, загрузчик и сервер** выставляются по каталогу;
- **добавили мод в `items`** — он скачается у всех;
- **убрали мод из `items`** — удалится у всех (только поставленный из каталога);
- **сменили `version` у мода** — у всех заменится файл;
- **моды сами не обновляются**, когда на Modrinth выходит новая версия. Поэтому версию
  лучше указывать явно: без `version` она выбирается один раз при первой установке;
- **память** применяется только при создании сборки — настройку игрока не перетирает.

Что остаётся за игроком: выключенный им мод не включается обратно, свои моды и сборки,
созданные вручную или импортированные, лаунчер не трогает. Если игрок удалил
рекомендуемую сборку, она не будет создаваться заново — вернуть её можно через
«+ Добавить → Из каталога».

## Проверка перед публикацией

```powershell
dotnet run --project tools/STlauncher.Cli -- build-plan --catalog catalog.json
```

Покажет, какие моды войдут в сборку и какие версии будут выбраны. Ошибка в `id` или
версии обнаружится здесь, а не у игроков.
