# Обновления и зеркало

Лаунчер обновляется через Velopack: релиз собирается по тегу `v*` и публикуется в GitHub
Releases, а установленная сборка читает тот же фид. Это работает, пока GitHub доступен.

## Проблема

У части игроков GitHub недоступен: TLS-соединение обрывается на рукопожатии, и проверка
обновлений падает с сообщением

```
The SSL connection could not be established, see inner exception.
```

Само сообщение бесполезно — оно не называет причину и ничего не предлагает. Лаунчер теперь
разбирает цепочку исключений до конца и говорит по-человечески: «не удалось связаться с
сервером обновлений — похоже, доступ блокирует провайдер или антивирус», плюс показывает
кнопку «Скачать вручную». Настоящая причина пишется в лог.

Но главная ловушка в другом: **исправление, доставляемое через GitHub, не доедет до того,
у кого GitHub заблокирован.** Поэтому адрес фида вынесен в `catalog.json` — он лежит на
`raw.githubusercontent.com` (другая сеть доставки) и, как правило, доступен даже там, где
`github.com` и `api.github.com` уже нет.

## Текущее состояние

Зеркало развёрнуто: **`https://showtime-updates.moh1topuk.workers.dev/`** и прописано в
`catalog.json` как `updateFeedUrl`. Проверено библиотекой обновлений самого лаунчера
(Velopack `SimpleWebSource`): фид читается, последняя версия и пакет находятся.

Воркер отдаёт и сам каталог — `/catalog.json`. Лаунчер (начиная с версии, где это
появилось) пробует его, если каталог с GitHub не загрузился. Иначе игрок с полностью
заблокированным GitHub никогда не узнал бы адрес зеркала: он приходит в каталоге, а каталог
лежит на том же GitHub. Этот адрес зашит в лаунчер (`AppSettings.CatalogMirrorUrl`) и
используется только для стандартного каталога — вручную заданный адрес каталога
подменять чужим нельзя.

Ссылка на установщик для тех, кто не может скачать его с GitHub:
`https://showtime-updates.moh1topuk.workers.dev/STlauncher-win-Setup.exe`

## Зеркало на Cloudflare

Воркер [`docs/updates/worker.js`](updates/worker.js) отдаёт фид и пакеты, забирая их с
GitHub на своей стороне. Ничего заливать вручную не нужно: публикация релиза остаётся
прежней, зеркало просто проксирует последний релиз.

Настройка — как у сборщика статистики (см. [MONITORING.md](MONITORING.md)), DNS трогать не
нужно:

1. *Workers & Pages* → *Create* → имя, например `showtime-updates` → *Deploy*.
2. *Edit code* → вставить `docs/updates/worker.js` → *Deploy*.
3. *Settings* → *Variables and Secrets*:

   | Тип | Имя | Значение |
   | --- | --- | --- |
   | Text | `REPO` | `moh1topuk-jpg/STlauncher` |
   | Secret | `TOKEN` | только если репозиторий приватный; для публичного не нужен |

4. Проверить: `https://showtime-updates.<аккаунт>.workers.dev/releases.win.json` должен
   отдать JSON с версией, а `/health` — `ok`.
5. Прописать в корень [`catalog.json`](../catalog.json):

   ```json
   "updateFeedUrl": "https://showtime-updates.ваш-аккаунт.workers.dev/",
   ```

Дальше лаунчер сам переключится на зеркало при следующем запуске — **новая версия для
этого не нужна**, что и есть смысл затеи. Убрать строку — вернётся GitHub.

## Как это устроено внутри

- поле пустое или отсутствует → `GithubSource`, как раньше;
- поле задано → `SimpleWebSource` с этим адресом;
- адрес применяется в момент загрузки каталога, до первой проверки обновлений;
- ошибки классифицируются в `Core/Http/NetworkFailure.cs` (`Blocked`, `NoConnection`,
  `Timeout`, `HttpError`) — этим же кодом стоит пользоваться и другим сетевым местам.

## Если и зеркало недоступно

Лаунчер показывает кнопку «Скачать вручную», которая открывает страницу релизов. Это
последний рубеж: обновиться руками можно всегда, установщик поверх старой версии сохраняет
сборки и настройки — они лежат в `%APPDATA%\STlauncher`, отдельно от самой программы.
