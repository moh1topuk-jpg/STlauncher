# Подпись кода

## Коротко

Бесплатного сертификата подписи кода, который убирает предупреждение SmartScreen,
**не существует**. Это не вопрос поиска «правильного» сайта: публичные удостоверяющие
центры (CA) выдают такие сертификаты только после проверки личности и за деньги, а с
июня 2023 года по требованиям CA/Browser Forum закрытый ключ обязан храниться в
аппаратном модуле (HSM или USB-токен) — файла `.pfx` больше не выдают.

Подделка или использование чужого сертификата — это подлог и кража личности, а не
«бесплатный вариант». Практический риск тоже высок: CA отзывает такой сертификат, и
**все** выпущенные сборки разом становятся недоверенными, а владелец ключа получает
претензии от CA и от того, чьё имя было использовано.

Ниже — что реально можно сделать бесплатно.

## Бесплатные варианты, которые работают

### 1. Attestation сборки в GitHub Actions (уже настроено)

В `.github/workflows/ci.yml` добавлен шаг `actions/attest-build-provenance`. Это
криптографическое доказательство, что файл собран именно этим workflow из этого
репозитория. Бесплатно для публичных репозиториев.

Пользователь проверяет так:

```powershell
gh attestation verify STlauncher-win-Setup.exe -R moh1topuk-jpg/STlauncher
```

Это **не** снимает предупреждение SmartScreen, но даёт то, ради чего обычно нужна
подпись: гарантию, что бинарник не подменён и собран из открытого исходника.

### 2. Контрольные суммы SHA-256 (уже настроено)

При релизе создаётся `SHA256SUMS.txt` и прикрепляется к релизу. Пользователь сверяет:

```powershell
Get-FileHash .\STlauncher-win-Setup.exe -Algorithm SHA256
```

### 3. Самоподписанный сертификат (бесплатно, ограниченно)

Бесплатно и легально, но SmartScreen его не признаёт. Полезен, чтобы:

- пользователь один раз импортировал ваш `.cer` в «Доверенные корневые центры» и
  дальше видел корректную подпись и издателя;
- проверять целостность сборок внутри команды.

```powershell
.\scripts\new-dev-cert.ps1
.\scripts\sign-release.ps1 -Thumbprint <отпечаток> -Version 0.1.0
```

### 4. SignPath.io Foundation — бесплатная подпись для Open Source

https://signpath.io/ — программа для открытых проектов: выдают настоящий
сертификат и подписывают через свой сервис бесплатно. Требуется заявка и соответствие
их критериям (проект должен быть OSS, с публичным репозиторием и историей).
Проверьте актуальные условия и примут ли проект вашего типа.

### 5. Бесплатные сертификаты для Open Source от CA

Часть удостоверяющих центров выдаёт бесплатные сертификаты подписи кода
open-source проектам (например, у Certum была такая программа). Условия и доступность
меняются, а для заявителей из России большинство западных CA сегодня закрыто —
проверять нужно точечно и актуально.

### 6. Дистрибуция через winget

Манифест в winget делает установку стандартной и проверяемой (там фиксируется
SHA-256). Сам сертификат не заменяет, но повышает доверие и удобство.

## Если сертификат всё-таки появился

Workflow уже готов: положите в секреты репозитория

| Секрет | Значение |
| --- | --- |
| `CODE_SIGNING_CERT_BASE64` | `.pfx` в base64 (только для self-signed/внутренних) |
| `CODE_SIGNING_CERT_PASSWORD` | пароль от `.pfx` |

и шаг подписи включится автоматически. Для сертификата на HSM/токене (OV/EV от
публичного CA) этот путь не подходит — нужен либо self-hosted runner с токеном, либо
сервис вроде Azure Artifact Signing, либо `vpk pack --azureTrustedSignFile`.

Обязательно используйте **timestamping** (`/tr`): без него подпись перестанет
действовать после истечения сертификата, и старые сборки потеряют доверие.

## Про SmartScreen

- **EV-сертификат** исторически давал репутацию сразу.
- **OV-сертификат** репутацию набирает постепенно, первые загрузки пользователи
  всё равно видят предупреждение.
- **Без сертификата** пользователь видит «Windows защитила ваш компьютер» и должен
  нажать «Подробнее» → «Выполнить в любом случае». Для открытого проекта, который
  скачивают с GitHub Releases, это обычная практика — поэтому и важны пункты 1 и 2:
  они дают пользователю способ проверить, что файл подлинный.
