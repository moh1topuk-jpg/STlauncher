# Сборщик статистики (`showtime-stats`)

Здесь два файла:

| Файл | Что это | Куда идёт |
| --- | --- | --- |
| `worker.js` | весь воркер; страница `/dashboard` уже вложена в него (константа `DASHBOARD_HTML`) | в редактор воркера в Cloudflare |
| `dashboard.html` | исходник той же страницы, для правки и просмотра | никуда отдельно не загружается |

Как воркер создаётся с нуля, какие у него биндинги и секреты — в
[docs/monitoring.md](../../docs/monitoring.md). Ниже — только обновление.

## Обновить воркер (сигнатуры падений, таблица на /dashboard)

Новых биндингов, переменных и секретов **не нужно**: используются те же `STATS` (KV),
`USAGE` (Analytics Engine, dataset `stlauncher_usage`), `CF_ACCOUNT_ID` и `CF_API_TOKEN`.
Число записей в KV не меняется: падения пересчитываются в том же запуске по расписанию,
что и раньше.

1. Cloudflare → *Workers & Pages* → `showtime-stats` → *Edit code*.
2. Выделить весь код в `worker.js` редактора и заменить его содержимым
   [`workers/stats/worker.js`](worker.js) из репозитория (целиком, один файл).
3. *Deploy*.
4. Открыть `https://showtime-stats.moh1topuk.workers.dev/dashboard`. Таблица «Падения
   игры» появится в новом виде после ближайшего пересчёта (раз в 5 минут; страница
   обновляется сама раз в минуту). JSON — `https://showtime-stats.moh1topuk.workers.dev/`,
   поле `launcher.crashes`.

`dashboard.html` отдельно загружать не нужно: он уже лежит внутри `worker.js`.

Откатить — вставить прошлую версию `worker.js` (история файла на GitHub) и *Deploy*.
Данные при этом не теряются: новое поле просто перестаёт читаться.

## Что изменилось в данных

Старые лаунчеры продолжают работать как раньше: формат пинга тот же, новое поле
необязательное.

| Поле Analytics Engine | Что в нём |
| --- | --- |
| `blob7` | причина падения (`Unknown`, `WindowsError`, `GraphicsDriverCrash`, …) |
| `blob8` | мод-виновник; для `WindowsError` — код Windows и его вид: `0xC0000005 AccessViolation`; для `GraphicsDriverCrash` — производитель видеокарты; для `OverlayCrash` — оверлей |
| `blob10` | **новое.** Сигнатура падения, до 120 знаков: `java.lang.NullPointerException @sodium` или `EXCEPTION_ACCESS_VIOLATION in amd-driver`. У лаунчеров до этой версии пусто |
| `double1` | код выхода игры (как и раньше) |

Сигнатура — это только имя класса исключения, id мода из стека (лишь тех модов, что
есть в сборке) или метка из фиксированного списка (`amd-driver`, `nvidia-driver`,
`intel-driver`, `jvm`, `java`, `lwjgl`, `rtss`, `discord-overlay`, `obs-hook`, …,
`native` для всего остального). Сообщения исключений, пути, имена файлов, ники и адреса
в неё не попадают; воркер дополнительно отбрасывает всё, что не похоже на такую строку.

`launcher.crashes` в JSON теперь сгруппирован по причине, subject, сигнатуре, версии игры
и коду выхода; у каждой строки есть `n` (падений) и `installs` (разных установок, через
`count(DISTINCT blob1)` — Analytics Engine это поддерживает). Если запрос с `DISTINCT`
когда-нибудь будет отклонён, воркер повторит его без этой колонки, и на странице столбец
«Установок» просто пропадёт.

## Править страницу

Править `dashboard.html`, потом вложить его в `worker.js` вместо текста между
``const DASHBOARD_HTML = String.raw` `` и закрывающей `` `; ``. В странице нельзя
использовать обратную кавычку и `${`: они ломают `String.raw`. Проверка синтаксиса
воркера: `node --check workers/stats/worker.js`.
