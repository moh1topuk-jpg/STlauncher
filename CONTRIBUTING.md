# Как вносить изменения

## Сборка и тесты

```powershell
dotnet build
dotnet test
dotnet run --project src/STlauncher.App
```

Логика живёт в `STlauncher.Core` и покрывается тестами в `tests/`. Интерфейс
(`STlauncher.App`) — тонкий слой поверх неё. Исправление в ядре приходит вместе с тестом,
который без исправления падал.

## Список изменений

**Каждое изменение, заметное игроку, записывается в [`CHANGELOG.md`](CHANGELOG.md)** в
раздел `## [Не выпущено]`, в том же коммите или PR, что и само изменение.

- Пишем для игрока: что изменилось для него, а не какие файлы поправлены.
  «Сборки из TLauncher снова запускаются», а не «исправлен парсинг GameArgument».
- Разделы: **Добавлено**, **Изменено**, **Исправлено**, **Удалено**, **Безопасность**.
- Внутренние правки без видимого эффекта (рефакторинг, тесты, CI) не записываются.

При выпуске `## [Не выпущено]` переименовывается в `## [X.Y.Z] — ГГГГ-ММ-ДД`, над ним
заводится новый пустой `## [Не выпущено]`, а внизу добавляется ссылка на сравнение версий.
CI не выпустит релиз, если раздела для версии нет, — текст из него становится описанием
релиза на GitHub.

## Коммиты

Формат [Conventional Commits](https://www.conventionalcommits.org/ru/): `feat:`, `fix:`,
`docs:`, `chore:`, `refactor:`, `test:`, `ci:`, с областью в скобках —
`fix(import): …`. В теле — почему сделано так, а не иначе.

## Выпуск версии

См. [docs/updates.md](docs/updates.md#как-выпускается-версия).

## Чего не коммитить

Ключи и токены (в том числе ключ Top-Minecrafter — он хранится только в секрете
Cloudflare Worker), `settings.json`, сертификаты, собранные файлы. Репозиторий публичный.
