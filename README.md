# STlauncher

Открытый лаунчер Minecraft с офлайн-режимом (вход по нику), поддержкой всех версий,
мод-лоадеров и интеграцией собственного сервера через пресет.

> Не связан с Mojang Studios и Microsoft. Minecraft — торговая марка Mojang Studios.

## Возможности

- **Все версии** — релизы, снапшоты и старые альфы/беты из `version_manifest` Mojang.
- **Офлайн-вход** — UUID v3 генерируется из ника по алгоритму `OfflinePlayer:<ник>`, полностью совместим с ванильным.
- **Авто-загрузка Java** — поиск установленной JRE, при отсутствии — автоматическое скачивание Adoptium JRE нужной мажорной версии.
- **Мод-лоадеры** — Fabric, Quilt (через profile JSON), Forge, NeoForge (через installer).
- **Сборки** — центральная сущность: версия игры, лоадер, память, разрешение, пресет сервера и набор модов в одной папке `instances/`. Из сборки два перехода: **каталог модов** и **настройки сборки**.
- **Каталог модов** — браузер Modrinth прямо в сборке: поиск, 19 категорий, сортировка, логотипы, описания. Версия мода подбирается под версию игры и лоадер сборки. Ключи не нужны.
- **Моды сервера** — свой список модов с описаниями в `catalog.json`; отмеченные галочкой ставятся автоматически перед запуском.
- **Настройки сборки** — версия, лоадер, память, разрешение, доп. аргументы и список установленных файлов (вкл/выкл, удаление).
- **Модпаки** — импорт `.mrpack` с проверкой хэшей и распаковкой overrides.
- **Свой сервер** — пресет в отдельной вкладке, авто-добавление сервера в `servers.dat` для любой версии, быстрый вход через `--quickPlayMultiplayer`.
- **Скины** — отображение головы по нику.
- **Готово из коробки** — при первом запуске лаунчер сам сверяется с `catalog.json` на GitHub,
  создаёт рекомендуемую сборку и подтягивает её моды в фоне. Играть можно одной кнопкой,
  заходить в раздел «Сборки» не нужно.
- **Мониторинг сервера** — онлайн за 24 часа или 7 дней, средний и пиковый онлайн;
  история берётся из общего сборщика ([docs/MONITORING.md](docs/MONITORING.md)), а если
  его нет — из собственных замеров лаунчера.
- **Авто-обновление** — через Velopack (дельта-обновления, самоподмена).

## Требования

### Для игрока
Ничего. Приложение поставляется одним self-contained `.exe`, Java скачивается автоматически.

### Для разработки
- Windows 10/11
- [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)

## Сборка и запуск

```powershell
dotnet build STlauncher.sln
dotnet test STlauncher.sln
dotnet run --project src/STlauncher.App
```

Публикация одним файлом:

```powershell
dotnet publish src/STlauncher.App -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true
```

```
    Assets/               asset index, objects, virtual/legacy

    Auth/                 офлайн-авторизация (UUID v3)

    Mods/                 менеджер mods/ и Modrinth API
    Modpacks/             импорт .mrpack

  STlauncher.App/         Avalonia UI (MVVM)
tools/
  STlauncher.Cli/         CLI-харнесс для отладки и сквозных проверок
tests/
  STlauncher.Core.Tests/  xUnit
```

## CLI

Отдельный консольный проект — удобен для отладки и сквозных проверок без GUI:

```powershell
dotnet run --project tools/STlauncher.Cli -- versions --all
dotnet run --project tools/STlauncher.Cli -- java
dotnet run --project tools/STlauncher.Cli -- loaders fabric 1.20.1
dotnet run --project tools/STlauncher.Cli -- install-loader fabric 1.20.1
dotnet run --project tools/STlauncher.Cli -- plan 1.20.1
dotnet run --project tools/STlauncher.Cli -- prepare 1.20.1 Steve
dotnet run --project tools/STlauncher.Cli -- run 1.20.1 Steve --loader fabric --server play.example.com
dotnet run --project tools/STlauncher.Cli -- modpack pack.mrpack
```

`prepare` скачивает всё, собирает команду и печатает её (без запуска игры) — так
проверяется весь путь, кроме самого запуска. `run` дополнительно запускает игру.

## Данные

Всё хранится в `%APPDATA%\STlauncher`: версии, библиотеки, assets, рантаймы Java,
инстансы и `settings.json`.

## Сборки

**Сборка** — это профиль запуска: версия игры, загрузчик, память, разрешение,
дополнительные аргументы, пресет сервера и набор модов из каталога. У каждой сборки
своя папка в `instances/`, свои моды, сейвы и `servers.dat`; параметры лежат в
`instances/<id>/instance.json`. Старые настройки из `settings.json` автоматически
переносятся в сборку «Default» при первом запуске новой версии.

Раздел **Сборки** позволяет:

- увидеть список сборок с версией и загрузчиком;
- создать новую, **сделать копию** существующей (копируется только определение —
  настройки и набор модов, файлы и миры остаются на месте) и переименовать;
- посмотреть, сколько модов в сборке, и перейти к их выбору;
- удалить сборку вместе с её файлами.

Моды отмечаются галочками на странице **Каталог** и устанавливаются перед каждым
запуском (с проверкой хэшей, поэтому повреждённый файл скачается заново).

### Рекомендуемая сборка синхронизируется сама

Сборка, созданная из каталога, хранит `catalogBuildId` и на **каждом старте** приводится
в соответствие с `catalog.json`: версия игры, загрузчик, адрес сервера и список модов.
Недостающие файлы докачиваются в фоне, а кнопка «Играть» дожидается этой докачки.

- сборки, созданные вручную (и копии), не трогаются — у них нет `catalogBuildId`;
- память, разрешение и доп. аргументы применяются только при создании: настройку
  ползунком памяти синхронизация не перетирает;
- сборка, установленная предыдущими версиями лаунчера, распознаётся по имени либо по
  совпадению версии, загрузчика и набора модов — дубликат не появится, даже если вы её
  переименовали;
- если сборку удалить, лаунчер это запомнит (`dismissedBuildIds` в `settings.json`) и не
  будет создавать её заново. Вернуть — кнопкой «Добавить рекомендуемую сборку».

### Импорт сборок из других лаунчеров

*Сборки → Найти сборки других лаунчеров* ищет готовые сборки в `.minecraft` (официальный
лаунчер, TLauncher), Prism/MultiMC, CurseForge, Modrinth App, GDLauncher и ATLauncher, а
также в любой папке, указанной вручную. Загрузчик определяется по тому, что профиль
реально запускает.

Для каждой сборки на выбор два режима:

- **Подключить на месте** — ничего не копируется, сборка запускается из своей папки. Папка
  остаётся общей с тем лаунчером: миры и моды у вас одни на двоих. Удаление сборки здесь
  чужую папку не трогает никогда.
- **Скопировать к себе** — сборка становится независимой. Копируются миры, моды, конфиги и
  настройки; кэши (`assets`, `libraries`, `versions`) — нет, лаунчер докачает их сам. Объём
  показывается до импорта.

Непригодные сборки (например, папка версии без JSON-профиля) не исчезают молча, а
показываются в списке с причиной. Уже подключённые повторно не предлагаются.

### Ник

При первом запуске генерируется читаемый ник вида `SwiftFox42` — общий `Player` означал бы
один и тот же офлайн-UUID и один скин у всех игроков сервера. Рядом с полем ника есть
кнопка «↻» для другого варианта.

## Запуск и закрытие

Лаунчер определяет момент, когда игра действительно стартовала (по маркерам в логе,
с таймаутом как страховкой), и дальше действует по настройке
**После запуска Minecraft**: оставить открытым, свернуть или закрыть лаунчер.
Процесс игры при этом **не зависит** от лаунчера — закрытие окна не завершает
Minecraft. Полный лог игры пишется в `%APPDATA%\STlauncher\logs`.

## Бэкапы

Страница **Настройки** → *Бэкапы*. Делаются по понятным событиям, а не по таймеру:

- **Раз в сутки перед запуском** — не чаще одного раза в 24 часа;
- **Перед установкой или изменением модов** — перед установкой элементов сборки,
  импортом модпака, установкой или удалением мода;
- **Перед каждым запуском** — если нужно всегда.

Плюс кнопка ручного бэкапа. В архив попадают `saves`, `config`, `mods`,
`resourcepacks`, `shaderpacks`, `options.txt` и `servers.dat`. Настраиваются лимит
количества и суммарного размера; лишние копии удаляются, самая свежая не удаляется
никогда. Фонового таймера нет: правило «раз в сутки» проверяется в момент запуска
игры или изменения модов.

## Технические параметры

Всё системное (выбор Java, адрес каталога, проверка обновлений,
консоль с логом) вынесено в раздел **Для разработчиков** и появляется только когда
включена галочка *Консоль разработчика*. Обычный пользователь видит только игровые
настройки.

## Каталог контента

Раздел **Content** показывает список модов с описанием, который вы ведёте сами.
Шаблон: [docs/catalog.example.json](docs/catalog.example.json), а рабочий каталог
лежит в корне репозитория — [catalog.json](catalog.json).

По умолчанию лаунчер берёт каталог из репозитория:

```
https://raw.githubusercontent.com/moh1topuk-jpg/STlauncher/main/catalog.json
```

Значит, чтобы добавить мод или рекомендуемую сборку, достаточно отредактировать
`catalog.json` (хоть через веб-интерфейс GitHub) — **новая версия лаунчера не нужна**.
Адрес меняется в Настройках в разделе «Для разработчиков».

**Веб-сервер не обязателен.** Каталог можно задать тремя способами:

| Способ | Где | Когда обновляется |
| --- | --- | --- |
| URL | Settings → *Content catalog URL* (`https://…/catalog.json`) | сразу после правки файла на сервере |
| Локальный файл | тот же поле, но путь (`C:\...\catalog.json`) или `file:///...` | при каждой загрузке |
| «Положил рядом» | `%APPDATA%\STlauncher\catalog.json` | при каждой загрузке, ничего настраивать не нужно |

Приоритет: URL/путь → кэш скачанной копии (`meta/catalog.json`) → файл рядом с
`settings.json`. Благодаря кэшу раздел работает и когда сервер недоступен.

Если хостинга нет вовсе, проще всего держать `catalog.json` в этом же репозитории
(правки — через веб-интерфейс GitHub) и указать ссылку на raw-файл после того, как
репозиторий станет публичным. Подойдёт и любой бесплатный статический хостинг.

Схема (`schemaVersion: 1`) состоит из секций и элементов:

```json
{
  "schemaVersion": 1,
  "sections": [
    {
      "id": "required",
      "title": "Обязательные моды",
      "description": "Без них сервер не пустит",
      "items": [
        {
          "id": "sodium",
          "type": "mod",
          "name": "Sodium",
          "description": "Повышает FPS",
          "required": true,
          "source": { "kind": "modrinth", "project": "sodium" }
        }
      ]
    }
  ]
}
```

Источники (`source.kind`):

| kind | Поля | Поведение |
| --- | --- | --- |
| `modrinth` | `project`, необязательный `version` | Без `version` подбирается версия под версию игры и лоадер инстанса |
| `direct` | `url`, `fileName`, `sha1`/`sha512` | Прямая ссылка с вашего сервера |

Типы (`type`): `mod`, `resourcepack`, `shaderpack`, `config`, `other`.
Каждый тип раскладывается в свою папку, а поле `targetPath` задаёт путь вручную —
именно оно позволяет добавлять новые типы контента **без обновления лаунчера**.
Неизвестный `type` не ломает каталог: элемент просто требует явного `targetPath`.

### Рекомендуемые сборки

Тот же файл может описать готовые сборки — они появятся в списке на странице
**Каталог** и применяются одним выбором:

```json
"builds": [
  {
    "id": "showtime-main",
    "name": "Сборка Showtime",
    "description": "Версия, загрузчик и обязательные моды одним выбором",
    "gameVersion": "1.20.1",
    "loader": "fabric",
    "memoryMb": 4096,
    "serverName": "Showtime",
    "serverAddress": "mc.showtime.su",
    "items": ["sodium", "lithium", "server-mod"]
  }
]
```

Выбор сборки выставляет версию, загрузчик, память и сервер, а перечисленные `items`
отмечаются галочками и **устанавливаются перед запуском**. Ссылку на каталог можно
держать на raw-URL из git, тогда обновление сборок не требует новой версии лаунчера.

### Как обновляется сборка

**Файл каталога в репозитории — источник истины**, а не Modrinth. Это значит:

- **добавили мод в `items`** → он скачается у всех, кто играет эту сборку;
- **убрали мод из `items`** → он удалится у всех (только поставленные из каталога,
  вручную добавленные файлы не трогаются);
- **моды сами не обновляются** при выходе новой версии на Modrinth — сборка
  воспроизводима. Чтобы обновить конкретный мод, укажите версию явно:

```json
{ "id": "sodium", "name": "Sodium", "source": { "kind": "modrinth", "project": "sodium", "version": "0.8.14+mc1.21.11" } }
```

Без поля `version` версия выбирается один раз при первой установке (стабильный релиз
предпочтительнее беты и альфы) и дальше не меняется. Проверить весь список сборки
можно командой `build-plan`.

Проверка из CLI:

```powershell
dotnet run --project tools/STlauncher.Cli -- catalog
dotnet run --project tools/STlauncher.Cli -- catalog-install sodium --instance default --game 1.20.1 --loader fabric
```

## Мониторинг

Вкладка **Сервер** показывает онлайн за 24 часа или 7 дней. Промежутки, когда данных нет,
показаны отдельно от нулевого онлайна: это пропуск, а не «никого не было».

Данные берутся из двух источников, в таком порядке:

1. **Сборщик статистики** — отдельный Cloudflare Worker опрашивает API мониторинга раз в
   пять минут и публикует историю одним JSON. Тогда график полный независимо от того,
   когда у игрока был открыт лаунчер, и сразу видны средний онлайн за неделю, рекорд с
   датой, аптайм и место в рейтинге. Настройка — [docs/MONITORING.md](docs/MONITORING.md),
   адрес публикуется полем `serverStatsUrl` в `catalog.json`, без новой версии лаунчера.
2. **Собственные замеры** — если сборщик не настроен или недоступен. Замер раз в пять
   минут, пока окно открыто, плюс замер при открытии вкладки. История лежит в
   `server-history.json`, хранится 14 дней и привязана к адресу сервера.

Готового бесплатного API с историей онлайна не существует (проверено — см. таблицу в
[docs/MONITORING.md](docs/MONITORING.md)), поэтому историю приходится собирать самим. Ключ
API мониторинга остаётся в сборщике и в лаунчер не попадает: тем же ключом открываются
списки проголосовавших и донатов.

## Пресет сервера

Имя и адрес сервера берутся из рекомендуемой сборки (`serverName` / `serverAddress` в
`catalog.json`), а если она их не задаёт — из настроек лаунчера (`mc.showtime.su`).
Значит, адрес сервера можно поменять правкой каталога, без нового релиза.

Адрес автоматически добавляется в `servers.dat` инстанса при любом запуске, поэтому
сервер всегда виден во внутриигровом списке серверов.
Автовход происходит **только** по кнопке «Play on server» (`--quickPlayMultiplayer`),
обычный Play просто запускает игру.

## Откуда берётся контент

Весь контент ставится **без API-ключей**: моды и модпаки — с Modrinth по прямым
ссылкам из их же метаданных, собственные файлы — по `direct`-ссылкам.
Третьи стороны с обязательной авторизацией не используются.

## Релизы и обновления

Релиз собирается автоматически по тегу `v*` через Velopack (`vpk pack` / `vpk upload`)
и публикуется в GitHub Releases.

Если у части игроков GitHub недоступен (обрыв TLS-соединения), обновления переключаются
на зеркало одной строкой в `catalog.json` — без новой версии лаунчера, которая до них всё
равно бы не доехала. См. [docs/UPDATES.md](docs/UPDATES.md). Лаунчер проверяет обновления через `GithubSource`
(см. `UpdateService.RepositoryUrl` — **замените на свой репозиторий**).
Проверка доступна только в установленной сборке; при запуске из `dotnet run`
кнопка сообщает, что обновления недоступны.

Каждый релиз содержит:

- `SHA256SUMS.txt` — контрольные суммы артефактов;
- **attestation сборки** (GitHub) — криптографическое доказательство, что файл собран
  этим workflow из этого репозитория:
  `gh attestation verify <файл> -R moh1topuk-jpg/STlauncher`.

Про подпись кода (Authenticode), почему бесплатного варианта, снимающего
предупреждение SmartScreen, не существует и что реально можно сделать —
см. [docs/SIGNING.md](docs/SIGNING.md).
